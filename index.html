01

RealBench

Founder & sole engineer · Georgia Tech CREATE-X · Jun 2026 – present

Decides whether a robot is verifiably ready for its next test run, and never says “ready” when it can’t prove it.

Why this problem

Robots in test pipelines fail silently between runs: a publisher keeps running while its data goes stale, a fault stays latched, a joint sits off its home pose. The next run then starts on a robot that isn’t ready. In 100+ interviews, robotics engineers described 5–30 minutes of reset downtime per test cycle.

What we built

A Python tool that reads a robot’s URDF or MuJoCo model and its live ROS 2 telemetry, runs tiered liveness, health and pose checks, and returns one verdict with an exit code a CI pipeline can gate on. It is fail-closed: missing data counts as a failure. It’s published on PyPI and ran for 8.15 hours on a physical Clearpath Jackal.

What I learned

“Can’t verify” has to be its own state, because treating missing data as a pass is how silent failures ship. Continuous evaluation reveals what a single check can’t. Enumerating all 16,384 check-state combinations in tests proved the safety rule instead of sampling it.

02

NurturIQ

Founder & CTO · Georgia Tech CREATE-X · Dec 2025 – Jun 2026

Computer-vision screening research and RAG-based AI agents

Turned a phone camera into a research gaze sensor, so screening research didn’t need a dedicated eye tracker.

Why this problem

Families can wait many months for a developmental evaluation. We explored whether a phone camera could capture an objective gaze signal at home that clinicians could use to prioritize. It was a screening research tool, not a diagnostic.

What we built

A 120 fps iPhone capture pipeline and a FastAPI service that extracts face landmarks, aligns gaze to a timed stimulus protocol and computes session-level attention features. We also built a gamified calibration protocol with a gaze model trained on 41,528 labeled frames, and a parent care platform whose chat runs on LangGraph agents with hybrid retrieval (RAG).

What I learned

Measure the signal before tuning the model. Our features tracked horizontal gaze but barely moved vertically, which explained the model’s weak top/bottom accuracy better than any hyperparameter could. Differences between people outweighed the vertical signal, so per-user calibration matters more than model choice.

03

RTL Bug-Hunting Agent

Oct 2026 – present In progress

An AI agent that finds bugs in FPGA hardware designs (RTL) and proves them with simulation, not guesses.

Why this problem

Verification is where hardware projects spend much of their effort, and in safety-critical FPGA work every claim about a design needs evidence behind it.

What we’re building

First milestone: a FIFO demo where the agent generates test stimulus that exposes deliberately planted bugs, judged by a human-reviewed checker. Built so far: a tree-sitter Verilog parser that extracts each module’s name, ports (direction and width) and internal signals into JSON.

The principle

The same one as RealBench. The agent’s verdict has to come from a simulation result it can point to, never from the model’s confidence.
